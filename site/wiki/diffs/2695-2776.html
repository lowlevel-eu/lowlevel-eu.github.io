== RS232 ==
+
= RS232 =
−
Ähnlich wie bei der print(f)/cout - Methode kann man auch Daten/ASCII-Strings über die [[serielle Schnittstelle]] verschicken. Das hat den Vorteil, dass man mehr als nur 25 oder 50 Zeilen zeitgleich betrachten kann. Bei bochs werden die an die serielle Schnittstelle gegebenen Daten in eine Textdatei gegeben, diese kann später ggf. auch von weiteren Tools (z.B. grep) weiterverarbeitet werden. Zudem ist ein [[rs232]]-Treiber sowohl im RM als auch im PM relativ einfach zu schreiben. Interrupts müssen hierfür nicht verarbeitet werden können.

= bochs / qemu =
 
Falls man mit Fehlern wie Pagefaults, GPFs oder anderen Exceptions kämpft, ist es wichtig, dass man die Registerinhalte vor der Exception kennt. Um an diese zu kommen sind Debug-Funktionen in den Emulatoren ein wertvolles Werkzeug. Bei bochs kann dazu der integrierte Debugger benutzt werden.  
 
Falls man mit Fehlern wie Pagefaults, GPFs oder anderen Exceptions kämpft, ist es wichtig, dass man die Registerinhalte vor der Exception kennt. Um an diese zu kommen sind Debug-Funktionen in den Emulatoren ein wertvolles Werkzeug. Bei bochs kann dazu der integrierte Debugger benutzt werden.  
−
qemu stellt keinen eigenen Debugger zur Verfügung, ermöglicht aber eine Verbindung mit einem externen (siehe [[GNU Project Debugger und QEMU]]). Oft braucht man aber in Verbindung mit qemu gar keine komplexen Debug-Funktionen, wenn man nur an die Adresse rankommen muss, wo eine Exception auftritt. Denn qemu bietet den -d Parameter um verschiedene Dinge zu loggen. Meist benötigt man ein -d int um alle Interrupts aufzuzeichnen. Dabei muss man aber ein wenig aufpassen, da qemu bei einem Triplefault keinen Reset ausführt, das heißt er schreibt dann lauter GPFs in die Logdatei und diese wird dabei extrem groß. Man sollte qemu also möglichst schnell schließen, wenn ein Triplefault aufgetreten ist.

== Exception-Meldungen ==
+
= Exception-Meldungen =
−
Wenn der Kernel schon ein wenig weiter ausgebaut ist, und [[Ausgabe_2#Exceptions | Exceptions]] abfängt, können diese Meldungen so ausgebaut werden, dass sie alle nötigen Informationen ausgeben. Um die Registerinhalte auszugeben empfiehlt es sich, diese in der [[ISR]] für die Exceptions auf den Stack zu legen, und dem Exception-Handler einen Zeiger auf das zuletzt gepushte Register zu übergeben. Dabei sollte man darauf, dass nichts anderes zwischen dem Interrupt-Stack-Frame und den Registern liegt, da der Handler sonst nicht mehr wirklich an eip und esp aus dem Interrupt-Stack-Frame ran kommen kann. Der Exception-Handler kann dann eine nette Meldung mit allen nötigen Informationen ausgeben.

== objdump ==
+
= objdump =
−
Sobald man die Adresse hat, muss man daraus irgendwie auf die Codestelle schließen können. Dabei kann das GNU-Tool objdump eine große Hilfe sein. Dies ist aber nur möglich, wenn man ein Binärformat wie [[elf|ELF]] benutzt, bei flachen Binaries fehlen dem Tool nötige Informationen. objdump kann dabei mit dem Parameter -d Assembler-Code mit Adresse vor jeder Instruktion generieren. Wenn man den Code mit Debug-Infos (bei gcc mit dem Parameter -g) kompiliert und linkt kann objdump mit dem Parameter -S sogar den zugehörigen Quelltext der ursprünglichen Sprache anzeigen.
